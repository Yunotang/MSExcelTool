製作過程

我沒有寫程式，我在做決定

整個過程我做的事情，其實只有四件：回答問題、拍板、要求平行化、驗收。 程式碼一行都不是我打的 —— 但每一個會影響結果的判斷，都還是我下的。

01

它先掃描，而不是先動手

我只丟了一句「啟動 PRD/SDD Studio」。它掃過資料夾，發現只有 PRD 和 SDD、 沒有任何程式碼，於是先把兩份文件讀完，把它理解的東西講給我聽，等我確認。

02

它抓出三個我沒注意到的矛盾

這步是整件事的轉折。SDD 第 1.3 節寫「改用 React + FastAPI」， 但第 2.1、5、8 節整段還停在舊的 Streamlit 版本 —— 同一份文件有兩套打架的設計。 PRD 又另外指定 Node.js + PostgreSQL，跟 SDD 完全不同。 如果直接開工，這些矛盾會變成一堆互相衝突的程式碼。

03

我拍板，它照做

我選了 React + FastAPI，並開啟「MVP 快速模式」—— 先求整個系統跑起來，測試和逐頁驗證都簡化。它把被放棄的章節明確列進待辦， 沒有假裝那些矛盾不存在。

04

我要求平行化，它先寫「契約」

我說：把任務切成能同時做的，派 subagent 去。 它沒有直接分頭寫，而是先產出一份介面契約 —— 把 8 張資料表的欄位、每個函式的簽章、25 個 API 的格式全部定死， 然後才讓三個 AI 各自盲寫。

05

三路合流，零介面衝突

後端基礎層、後端應用層、前端三邊同時開工，彼此看不到對方的程式碼。 最後接起來時 18 項整合測試一次全過，一個欄位名都沒對錯 —— 因為大家照的是同一份契約。

整個過程最關鍵的一句話 「幫我把 TASK 切成可以平行執行的任務，讓 subagent 幫你用最快速的方式開發完成， 若過程有需要 pip install，請先建立虛擬環境，檢查第三方庫安全性，確認安全後就可以安裝。」

後半句也有用：它因此查出原本文件指定的 JWT 套件有兩個已知漏洞，主動換成了維護中的替代品。

成果 · 怎麼用

雙擊一個檔案，就這樣而已

做出來的東西叫 SyncTask：給小團隊用的看板協作工具。 可以拖拉卡片改狀態、在任務底下討論、用 @ 提及同事、收站內通知。

四個步驟，第一次大約五分鐘

  1. 1
    雙擊 start.bat 第一次會自己裝好 Python 環境、下載前端套件、建立展示資料。 中途不用管它，跑完會自己啟動。
  2. 2
    開瀏覽器到 localhost:8021 只有一個網址、一個視窗。不需要同時開兩個終端機。
  3. 3
    用展示帳號登入 帳號 pm@synctask.dev，密碼 demo1234。 登入頁上有「填入展示帳號」按鈕，不用自己打。
  4. 4
    直接拖卡片試試看 把「設計登入頁 UI」從待處理拖到進行中； 點卡片會開右側詳情，可以改負責人、留言、用 @ 提及同事。
兩件事先講在前面。 第一次啟動因為要裝套件與建置前端，會等上幾分鐘，之後再開只要幾秒。 要停止服務，回到那個黑色視窗按 Ctrl + C。
